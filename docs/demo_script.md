# Local demo script

This script follows the six-page dashboard adapted from `DESIGN.md` and `RetailMind_Frontend_Brief.md`. The screenshots in `docs/screenshots/` show the actual local API and UCI workbook. All figures below come from the verified workbook hash in `reports/data_manifest.json`.

1. **Start locally.** Complete the README pipeline, then run `uvicorn retailmind.api:app --host 127.0.0.1 --port 8000` from the project environment. Check `/health` for `ready`, open `/ui/`, and keep `/docs` available for API inspection.
2. **Overview.** Select **Test · 01 Nov 2011**. Explain that the positive sales KPI uses only rows before this cutoff, includes anonymous purchases for analytics, and excludes returns. Point to the monthly table and GBP units. Switch to Validation and check that the snapshot ID and figures change together, then return to Test.
3. **Customers.** Enter customer `12384`, load the profile and the selected top-ten ItemCF list. Show RFM, distinct-invoice frequency, cutoff-safe product descriptions, repeat flags and evidence from historical items. Change the ranking model to ALS or Popularity and compare lists without suggesting scores are probabilities. Download the recommendation CSV and inspect its snapshot/model metadata.
4. **New customer and failure.** Select **New-customer recommendations** to show explicit Popularity mode with no customer ID. Enter a nonexistent ID to show 404 instead of silently treating a typo as new. If a bundle is deliberately absent in a controlled test, show the 503 error and request ID; do not modify live artifact files merely for a demo.
5. **Historical Replay.** Enter customer `12384` on Test. Show the pre-cutoff history and ranking first. Then select **Reveal outcomes** to load future purchases through the separate 30-day route. The ranking does not change after reveal. An observed top-ten overlap is an offline match, not evidence that the recommendation was shown to the customer.
6. **Products, Evaluation and Quality.** Search a product code or description, open ItemCF similar products, compare Popularity/ItemCF/ALS on the same test cohort, then inspect the frozen error slice and data-quality reconciliation. Emphasize 1,469 evaluated historical customers, selected ItemCF NDCG@10 0.166409 and 1,067,371 reconciled source rows. Show that the quality report covers the entire source period, while snapshot KPIs stop at the selected cutoff.

End with the model-card limits: no impression logs, no online experiment and no measured revenue lift. Do not claim a real-bundle Compose run, public hosting or a V1 release until each is verified.
