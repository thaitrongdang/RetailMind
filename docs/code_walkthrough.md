# Trace one real row through RetailMind

Use source row `bcbe73b35f5b7bab:1:296323` as a concrete example. It is in sheet `Year 2010-2011`, Excel row 296323: invoice `562882`, customer `12384`, stock code `22423` (REGENCY CAKESTAND 3 TIER), quantity 1, unit price GBP 12.75, timestamp 2011-08-10 11:23:00. These values were checked against the local classified Parquet; the source workbook itself remains ignored by Git.

1. `data/ingest.py` preserves raw fields and gives the row a stable ID from the workbook hash, sheet index and Excel row. It classifies this row as `sale_identified`; its positive line value is GBP 12.75. The cleaning report counts it among the 802,651 identified valid sale lines.
2. `data/snapshots.py` includes it in both validation (2011-09-01) and test (2011-11-01) history because its timestamp precedes both cutoffs. For test, `interactions.parquet` aggregates customer `12384` and stock `22423` by distinct historical invoices. `customers.parquet` holds the pre-cutoff RFM profile; `products.parquet` holds a description selected only from pre-cutoff history.
3. `models/catalog.py` maps customer and stock code to stable matrix indices. `models/itemcf.py` multiplies this customer's log-weighted item history by a sparse item-similarity matrix with the diagonal removed. For this customer, the first test recommendation is stock `22699`. Its explanation includes historical stock `22423` with a contribution of approximately 0.423765; other historical items also contribute. The exact ranking score is not a probability.
4. `service.py` chooses the frozen validation-selected ItemCF for this known customer and enriches the ranking with cutoff-safe descriptions, repeat flags, source model and evidence. `api.py` exposes this at `GET /recommendations?customer_id=12384&snapshot=test` with a request ID and model version. The provisional/final UI consumes this response; it must not rebuild the ranking algorithm.
5. `data/snapshots.py` separately writes future labels to `data/processed/outcomes/<snapshot_id>/labels.parquet`. Customer `12384` has a future purchase of stock `23084` at 2011-11-11 08:39:00. `evaluation/run.py` compares the frozen top-ten list with these labels. `GET /replay/outcomes` reads them only for historical replay. The recommendation service never loads them.

To inspect each artifact, run the README pipeline, then query the Parquet files with DuckDB or pandas. Row IDs and numeric example values are evidence for this checked workbook hash; a different source revision may change them. Future purchases are observed outcomes, not evidence of recommendation exposure or user preference.
